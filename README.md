# DocVision

Нативное приложение для macOS, которое конвертирует PDF в Markdown с помощью vision-language моделей через OpenAI-совместимый API. В первой версии поддерживается PDF на входе и Markdown на выходе.

## Возможности

- Выбор PDF и папки хранения результатов через системные диалоги macOS.
- По умолчанию результаты сохраняются в `~/.docvision/results`; выбранная папка запоминается между запусками. Имя Markdown-файла берётся из имени PDF, а отдельная кнопка позволяет указать путь к файлу вручную.
- Загрузка моделей из `GET /v1/models` и выбор модели из списка сервера.
- Отправка страниц PDF как PNG-изображений в `POST /v1/chat/completions`.
- Настройки количества страниц, размера пакета, режима и длительности таймаута, лимита токенов ответа.
- Два режима таймаута: жёсткий ограничивает полное время ответа конвертации; мягкий допускает долгую генерацию и проверяет доступность сервера запросом `GET /v1/models` каждые 5 секунд. Если keepalive не ответит за настроенное время, текущая конвертация отменяется.
- Лимит токенов ответа задаётся на страницу и масштабируется на размер пакета. Если API завершает ответ с `finish_reason=length`, диапазон страницы помечается в Markdown и предупреждением в preview.
- Редактируемый системный промт с восстановлением исходного текста. Промт сохраняется локально; API-ключ действует только в текущем запуске.
- Индикатор прогресса и отмена конвертации.
- Несколько независимых окон документов с отдельными PDF, настройками, промтами и результатами; очередь общая.
- Параллельная обработка страниц и нескольких документов с настройкой числа одновременных запросов (1–4). Соседние страницы объединяются согласно размеру пакета, а отдельные пакеты могут обрабатываться параллельно.
- Боковая панель миниатюр страниц PDF с переходом к странице, статусом генерации и действием перегенерации.
- Менеджер очереди страниц: просмотр статуса, изменение приоритета ожидающих страниц, отмена отдельных ожидающих задач и очистка завершённых записей.
- Перегенерация одной страницы заменяет её Markdown-раздел, сохраняет остальные страницы и сразу записывает обновлённый файл.
- Импорт и экспорт UTF-8 Markdown. Чистый экспорт удаляет маркеры страниц и разделительные линии `---`; вариант «С разметкой DocVision» сохраняет служебные комментарии для повторного импорта и перегенерации. Импортированный файл можно просматривать и редактировать; для перегенерации выберите соответствующий исходный PDF.
- Диагностика в окне Markdown: токены последнего ответа, скорость генерации и использование контекстного окна. Показываются метрики, которые сервер передаёт в `timings` и, для llama-server, в `/slots`.
- Отдельное окно Markdown с переключением между форматированным просмотром и редактированием; оно открывается при старте конвертации. Встроенный просмотр форматирует заголовки, абзацы, списки, цитаты, блоки кода, Markdown- и HTML-таблицы, распространённые HTML-блоки, ссылки и inline-выделение.
- В preview есть сплошное отображение и просмотр по страницам/диапазонам на основе HTML-комментариев. Служебные маркеры скрываются или показываются подсвеченными; в редакторе исходного Markdown строки-маркеры также выделяются.
- Результаты добавляются в preview по мере завершения запросов, в порядке номеров страниц. Несколько документов и пакеты страниц одного документа можно обрабатывать параллельно. Для пакета больше одной страницы модель получает просьбу разделить ответ комментариями с номерами страниц.
- Изменения в окне предпросмотра можно сохранить в выбранный `.md` файл.

Для продолжения работы с существующим результатом выберите PDF, нажмите **Импорт…** и загрузите Markdown с маркерами `<!-- DocVision: page-range 65–65 -->`. Миниатюры страниц с импортированными разделами отмечаются как готовые; используйте кнопку перегенерации у нужной страницы, затем нажмите **Экспорт…** или кнопку сохранения в preview. Импортированный исходный файл не перезаписывается автоматически. Для диапазона из нескольких страниц перегенерация отдельной страницы разрешена только если страницы разделены строками `---`.

Приложение не выбирает провайдера по имени модели. Укажите совместимый URL, например `http://localhost:11436/v1`, затем нажмите **Загрузить модели**. Для локального llama-server запустите сервер с VL-моделью и убедитесь, что он предоставляет OpenAI-совместимые `/v1/models` и `/v1/chat/completions`.

## Сборка и запуск

Требуются macOS 14+, Swift 6, инструменты командной строки Xcode и Python 3. Полный Xcode не требуется.

```bash
./Scripts/build-macos-app.sh
open .build/DocVision.app
```

Скрипт собирает приложение в `.build/DocVision.app` и встраивает иконку из `Assets/DocVision.icns`. Исходник SVG находится в `Assets/AppIcon.svg`. Приложение локально собрано и не подписано для распространения вне этой машины.

## Использование

1. Запустите OpenAI-совместимый сервер с VL-моделью.
2. В DocVision задайте API URL и при необходимости API key, затем загрузите список моделей и выберите нужную.
3. Выберите папку хранения результатов в настройках (по умолчанию `~/.docvision/results`) и затем PDF. Приложение сохранит Markdown с тем же именем в этой папке.
4. Настройте лимит страниц (`0` — весь документ), число страниц на запрос, таймаут, режим ожидания и лимит токенов на одну страницу. При запросе нескольких страниц бюджет умножается на их число. Жёсткий режим задаёт предельное время полного ответа. Мягкий режим подходит для медленной генерации: он останавливает работу только если сервер перестал отвечать на `/v1/models` в пределах таймаута.
5. Отредактируйте системный промт при необходимости и нажмите **Конвертировать**.

Страницы всегда передаются модели изображениями, включая PDF с текстовым слоем. Приложение сохраняет номер страницы в Markdown-комментариях и обновляет результаты атомарно после каждого ответа. Если активные сеансы указывают на один и тот же файл, для следующего используется имя с числовым суффиксом.

## Разработка

```bash
swift test
swift build
```

Для `swift test` нужен toolchain с модулем XCTest, совпадающий с установленным macOS SDK. Если `swift test` недоступен в текущей установке Command Line Tools, используйте smoke check ниже.

Проверку правил разбиения страниц также можно запустить напрямую на установленном Swift:

```bash
swiftc Sources/DocVision/ConversionPlan.swift Sources/DocVision/MarkdownPresentation.swift Sources/DocVision/MarkdownBlockParser.swift Sources/DocVision/OpenAICompatibleClient.swift Scripts/check-plan.swift -o /tmp/docvision-check-plan
/tmp/docvision-check-plan
```

Примеры PDF можно проверить на открытие и рендер первой страницы:

```bash
swiftc -framework AppKit -framework PDFKit Sources/DocVision/ConversionPlan.swift Scripts/check-pdf-samples.swift -o /tmp/docvision-check-pdfs
/tmp/docvision-check-pdfs
```
